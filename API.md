# The cast hub API

`cast.sethgholson.com` is the data hub for the cast. It serves everything needed to
**write in a character's voice, generate images of them, and generate their audio**.

Everything below is a static file generated by `scripts/build-site.py`, served by nginx,
fronted by Cloudflare. There is no server, no database and no auth. Every endpoint is a
plain `GET` and every endpoint sends `Access-Control-Allow-Origin: *`.

## Why this file and not `/openapi.json`

Judgment call, made deliberately.

OpenAPI earns its keep when it tells a client something the response cannot: which verbs
exist, which parameters are valid, what the auth scheme is, which status codes mean what.
This API has one verb, no parameters, no auth, and two status codes. Every payload shape is
already published as a JSON Schema at `/schema/*.json` — that is the machine-readable
contract, and it is the one the build actually validates against, so it cannot drift from
what is served. An OpenAPI document would be a *second* description of the same shapes with
nothing enforcing agreement between them, which is exactly how a spec starts lying.

So: **the schemas are the machine-readable contract, this file is the human one.** For
programmatic discovery without parsing Markdown, `cast.json` carries an `endpoints` block
with every URL, including a `{id}` template for the per-character ones.

If a consumer ever needs generated client code, revisit — but generate the OpenAPI *from*
the schemas rather than hand-maintaining it beside them.

## Endpoints

| URL | What it is |
|---|---|
| `/cast.json` | The registry. Identity for every cast member, plus asset counts and links. |
| `/assets/index.json` | Every asset across the whole cast, flat. One fetch, filter client-side. |
| `/<id>/assets.json` | Every asset for one character, plus their `voice` and `lora` blocks. |
| `/<id>/voice.json` | The voice profile — writing voice and speech direction. |
| `/style/vaudeville-1933.json` | The house style as data. `.md` source alongside it. |
| `/schema/asset.schema.json` | The uniform asset record. |
| `/schema/character.schema.json` | A cast member. |
| `/schema/voice.schema.json` | A voice profile. |
| `/schema/lora.schema.json` | A LoRA card. |
| `/<id>/sheet.png` | Canonical turnaround sheet — reference conditioning. |
| `/<id>/headshot.png` | Purpose-rendered square avatar. Never a crop of the sheet. |
| `/API.md` | This file. |

Cast ids: `seth`, `wilson`, `cadbury`, `ake`.

## The asset record

Every asset is the same shape whatever its kind — a turnaround sheet, a transparent pose
cutout, a voice sample and a LoRA card all read alike. A consumer that can parse one can
parse all of them.

```json
{
  "id": "wilson/pose/arms-crossed",
  "character": "wilson",
  "kind": "pose",
  "url": "https://cast.sethgholson.com/wilson/poses/arms-crossed.png",
  "mime": "image/png",
  "bytes": 88362,
  "sha256": "43e342ccb9179a951c0e8318bb7bd168c78a267bea5e62068ce544b9170a6a7d",
  "width": 1024, "height": 1024,
  "duration_s": null,
  "tags": ["arms-crossed", "front", "full-body", "standing", "transparent"],
  "caption": "Wilson standing with both arms folded across his body, front view, full body",
  "created": "2026-08-06",
  "source": "nano-banana-pro chained edit from wilson/pose/standing-neutral"
}
```

`kind` is one of `turnaround`, `headshot`, `portrait`, `sheet`, `pose`, `keyframe`,
`expression`, `style-plate`, `training-set`, `voice-sample`, `lora`.

`bytes`, `sha256`, `width`, `height` and `duration_s` are computed at build time from the
file itself. There is deliberately no way to hand-write them.

**On `caption`:** it describes pose, framing and background — never the style. That inverts
normal captioning intuition, and it is deliberate: in LoRA training, what you caption stays
editable and what you omit gets baked into the trigger token. The house style is the thing
we want baked in.

## Fetching a character's assets

```bash
curl -s https://cast.sethgholson.com/wilson/assets.json | jq '.counts'
```

Grab every transparent pose cutout for a compositor:

```bash
curl -s https://cast.sethgholson.com/wilson/assets.json \
  | jq -r '.assets[] | select(.kind=="pose") | "\(.id)\t\(.url)"'
```

From JavaScript, anywhere — CORS is open:

```js
const res  = await fetch("https://cast.sethgholson.com/wilson/assets.json");
const hub  = await res.json();

const poses = hub.assets.filter(a => a.kind === "pose");
const armsCrossed = poses.find(a => a.tags.includes("arms-crossed"));
document.querySelector("img").src = armsCrossed.url;

// Everything needed to render him, in one object:
console.log(hub.voice.speech.h3_voice_clause);   // audio direction for MiniMax H3
console.log(hub.lora);                            // weight cards, if any
```

One fetch for the whole cast, then filter:

```js
const all = (await (await fetch("https://cast.sethgholson.com/assets/index.json")).json()).assets;
const everyExpression = all.filter(a => a.kind === "expression");
```

Validate before trusting a payload:

```bash
pip install check-jsonschema
curl -sO https://cast.sethgholson.com/schema/asset.schema.json
curl -s https://cast.sethgholson.com/assets/index.json \
  | jq '.assets[]' | check-jsonschema --schemafile asset.schema.json -
```

## Rendering a character

Two halves, and both are required — dropping either measurably breaks identity.

1. **The pictures half:** feed `sheet_url` as reference conditioning.
2. **The words half:** inject `tokens` verbatim into the prompt. The sheet carries
   silhouette and costume; the tokens stop a model inventing a different design when
   reference conditioning runs weak.

Then prepend the shared style block, which is **never varied per render** — vary staging and
camera only:

```bash
STYLE=$(curl -s https://cast.sethgholson.com/style/vaudeville-1933.json | jq -r .style_block)
TOKENS=$(curl -s https://cast.sethgholson.com/cast.json \
  | jq -r '.cast[] | select(.id=="wilson") | .tokens')
```

`exclusion_block` goes on the end. It is phrased positively on purpose: FLUX.2 ignores
negative prompts entirely and Nano Banana treats them loosely, so exclusions have to be
stated as things that are true of the image.

## Voice

`/<id>/voice.json` has two halves for two consumers.

**Writing dialogue** — read `writing_voice`: diction, rhythm, tics, `never_says`, and sample
lines that only that character could have said.

**Generating audio** — read `speech.h3_voice_clause` and paste it into the *same* prompt as
the visuals. MiniMax H3 is a joint video+audio model driven by one prompt; TTS dubbed on
afterward is authored blind to the mouth movement H3 already rendered and can never sync.

For a clip that must be silent, use `negatives.silent` verbatim — the whole list. H3's audio
head is unsupervised if the prompt describes only visuals, and it defaults to garbled human
vocalisations. Keep `negatives.no_on_screen_text` in **every** prompt including ones that
want speech; it is a separate control and dropping it brings the lettering bug back.

`samples` is an array of asset records pointing at reference WAVs. It may be empty — voice
cloning is a separate project and this is the container for it.

## LoRA weights

The hub serves the **card**; GitHub serves the **weights**. `.safetensors` files run
50–400 MB, which would bloat every clone and land in the Docker image the site ships from.

Cards live in `/<id>/assets.json` under `lora`, and carry `download_url`, `sha256`, `bytes`,
`base_model`, `trigger`, `recommended_strength`, `trained_on` and `trained_at`.

```bash
CARD=$(curl -s https://cast.sethgholson.com/wilson/assets.json | jq '.lora[0]')
curl -sL "$(jq -r .download_url <<<"$CARD")" -o wilson.safetensors
echo "$(jq -r .sha256 <<<"$CARD")  wilson.safetensors" | sha256sum -c
```

`trained_on` holds asset ids resolvable in `/assets/index.json` — the derived weights left
the repo, but the images that made them did not.

Publish with `scripts/publish-lora.sh`. It validates the registry before uploading and again
afterwards, and it is the only supported way to write a card's `sha256` and `bytes`.

## Caching

Cache headers live in `nginx.conf`, and the numbers follow one rule: **stale canon is the
failure mode that has actually hurt here.**

| What | Browser | Edge |
|---|---|---|
| Images and audio | `max-age=86400` | `s-maxage=300` |
| Every JSON endpoint | `max-age=300` | `s-maxage=60` |

The edge is capped tight because purging Cloudflare is not available on the current API
token — a plain `max-age=86400` once left an old cast pinned at the edge for a day. JSON is
capped tighter still than the images: a stale sheet is a cosmetic regression, while a stale
`cast.json` points a consumer at an asset that no longer exists.

Filenames are stable across regeneration, so a URL that worked once keeps working. Cache on
`sha256` if you want to know whether bytes actually changed.
