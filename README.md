# the-cast

The canonical cast of [sethgholson.com](https://sethgholson.com) — a vaudeville troupe,
est. 1933. This repo is the single source of truth for who these characters are.

**cast.sethgholson.com is the data hub for the cast.** It does not just say who they are; it
serves everything needed to **write in a character's voice, generate images of them, and
generate their audio** — turnaround sheets, prompt tokens, a pose library, expression
close-ups, LoRA training sets and cards, and voice profiles. Every future consumer — a comic
strip compositor, a MiniMax H3 video, a site header, an agent writing dialogue — should be
able to fetch one URL and get what it needs.

Full endpoint reference and copy-pasteable examples: **[API.md](API.md)**, also served at
[cast.sethgholson.com/API.md](https://cast.sethgholson.com/API.md).

## What the hub serves

Every endpoint is a static file generated by `scripts/build-site.py`, CORS open, plain `GET`.

| URL | What it is |
|---|---|
| `/cast.json` | The registry: identity, tokens, props, asset counts, links. |
| `/assets/index.json` | Every asset across the whole cast, flat. One fetch, filterable. |
| `/<id>/assets.json` | Every asset for one character, plus `voice` and `lora` blocks. |
| `/<id>/voice.json` | Voice profile — writing voice and H3 speech direction. |
| `/style/vaudeville-1933.json` | The house style as data (the `.md` stays the source). |
| `/schema/*.json` | `asset`, `character`, `voice`, `lora` — publish so consumers can validate. |
| `/<id>/sheet.png`, `/<id>/headshot.png` | The canonical identity images. |
| `/API.md` | The reference. |

```bash
curl -s https://cast.sethgholson.com/wilson/assets.json | jq '.counts'
# { "expression": 6, "headshot": 1, "portrait": 1, "pose": 8,
#   "style-plate": 5, "training-set": 16, "turnaround": 1 }

# every transparent pose cutout, ready to composite
curl -s https://cast.sethgholson.com/wilson/assets.json \
  | jq -r '.assets[] | select(.kind=="pose") | "\(.id)\t\(.url)"'
```

```js
const hub = await (await fetch("https://cast.sethgholson.com/wilson/assets.json")).json();
const armsCrossed = hub.assets.find(a => a.kind === "pose" && a.tags.includes("arms-crossed"));
document.querySelector("img").src = armsCrossed.url;
console.log(hub.voice.speech.h3_voice_clause);  // audio direction for MiniMax H3
```

## Layout

```
cast/<id>/
  character.yaml    # identity: name, role, prompt tokens, props, accent, notes
  sheet.png         # canonical turnaround sheet
  headshot.png      # canonical square avatar — 1024x1024, purpose-rendered
  voice.yaml        # writing voice + speech direction -> /<id>/voice.json
  assets.yaml       # the asset manifest -> /<id>/assets.json
  lora.yaml         # LoRA cards (weights are NOT here — see below)
  assets/
    poses/          # transparent cutouts for compositing
    training/       # opaque stills for LoRA training
    expressions/    # face close-ups
    plates/         # character-free style plates
style/vaudeville-1933.md    # the locked house style — shared by every renderer
schema/*.schema.json        # asset, character, voice, lora
scripts/build-site.py       # registry -> public/. The single gate.
scripts/prepare-assets.py   # raw render -> registry-ready asset
scripts/publish-lora.sh     # weights -> GitHub Release, card -> registry
showcase/                   # strips worth showing off
```

## The asset contract

Every asset in the hub is described the same way whatever its kind — a turnaround sheet, a
pose cutout, a voice sample and a LoRA card all read as the same record
(`schema/asset.schema.json`). A consumer that can parse one can parse all of them.

Authors write only what a human knows, in `cast/<id>/assets.yaml`:

```yaml
assets:
  - file: assets/poses/arms-crossed.png
    kind: pose
    tags: [standing, arms-crossed, front, full-body, transparent]
    caption: Wilson standing with both arms folded across his body, front view, full body
    created: 2026-08-06
```

`build-site.py` measures the rest — `bytes`, `sha256`, `width`, `height`, `duration_s` —
from the file on disk. There is deliberately no way to hand-write them, because hand-written
metadata is how a registry starts lying.

**Captions describe pose, framing and background only — never the style.** This inverts
normal captioning intuition and it matters: in LoRA training, what you caption stays
editable and what you omit gets baked into the trigger token. The style is the thing we want
baked in; the background is the thing that must stay changeable.

## Where the bytes live

- **Small assets live in the repo** under `cast/<id>/assets/` — poses, training stills,
  expressions, style plates, voice samples. Keep each under ~2 MB and the repo under
  ~300 MB. Renders are quantised to a 256-colour palette by `prepare-assets.py`; the house
  style is sepia duotone shaded with halftone dots, so truecolour was paying for precision
  the art does not use (measured: 49 MB → 9.1 MB for Wilson's set, at RMSE 1.4–2.1).
- **LoRA weights do NOT go in git.** `.safetensors` files run 50–400 MB and would bloat
  every clone and land inside the Docker image the site ships from, for bytes nginx should
  never have been asked to serve. They are published as **GitHub Release assets** on this
  repo; `lora.yaml` carries the card that points at them. The hub serves the card, GitHub
  serves the weights.
- **Training sets stay in the repo, derived weights do not.** The images are small and they
  are the only link back from a LoRA to what made it (`trained_on`).

## How this gets consumed

- **Generation pipelines** feed `sheet.png` as reference conditioning and inject `tokens`
  verbatim into prompts. The sheet carries silhouette and costume; the tokens stop a model
  inventing a different design when conditioning runs weak. Both halves are required —
  dropping either one measurably breaks identity (we tested).
- **Compositors** pull `kind: pose` from `/<id>/assets.json` — transparent cutouts that all
  share one camera and figure scale, so they drop into a layout interchangeably.
- **Agents writing dialogue** read `/<id>/voice.json` → `writing_voice`.
- **Video** reads `/<id>/voice.json` → `speech.h3_voice_clause` and puts it in the *same*
  prompt as the visuals. H3 is a joint video+audio model; TTS dubbed on afterward is
  authored blind to the mouth movement H3 already rendered and can never lip-sync.
- **Avatars** use `headshot.png` — a rendered square portrait, never a crop of the sheet.
  Cropping the sheet is what we did first and it cut off chins and caught stray arms.
- **Scripts and agents** read `cast.json` — stable URLs, no YAML parsing, CORS enabled.

## Adding or changing a cast member

1. Edit or add `cast/<id>/character.yaml` (schema-validated), `sheet.png` and `headshot.png`.
   Optionally `voice.yaml`, `assets.yaml`, `lora.yaml`.
2. `python3 scripts/build-site.py` — the single gate. It fails loudly and with a located
   `FAIL <file>: <what>` line on a schema error, a missing sheet, a bad asset `kind`, a
   manifest pointing outside `assets/`, a typo'd manifest key, a duplicate asset id,
   unparseable YAML, or a `trained_on` referencing an asset that does not exist. There is no
   separate `validate.py` on purpose — one command, one gate, nothing to forget to run.
3. Commit, push. Deploy picks it up; every endpoint regenerates from the registry.

Filenames stay stable when regenerated — consumers never chase URLs.

## Adding assets

```bash
# 1. generate (nano-banana-pro; see the minimax-h3 skill for the measured rules)
# 2. post-process
python3 scripts/prepare-assets.py raw.png cast/wilson/assets/training/still-01.png

#    transparent cutouts need rembg — a dev-time tool, deliberately NOT a build dependency
python3 -m venv .venv-matte && .venv-matte/bin/pip install rembg onnxruntime
.venv-matte/bin/python scripts/prepare-assets.py --matte raw.png \
  cast/wilson/assets/poses/walking.png

# 3. declare it in cast/wilson/assets.yaml, then
python3 scripts/build-site.py
```

Two rules from `~/.claude/skills/minimax-h3/references/` that are not optional:

- **Generate poses as edits from one base plate, never independently.** Independent
  generation re-stages the shot — RMSE 85.3 against the base versus 39.3 for a chained edit.
  Wilson's set came back at 16.7–38.5.
- **Render cutouts on flat mid-grey `#808080`, never green** — diffusion bleeds backdrop
  colour and there is no despill node in this stack — then matte with BiRefNet.

`prepare-assets.py` crops the newspaper border nano-banana-pro draws on every render. It
does that even when the prompt forbids it as CRITICAL, because the style block opens with
"A single panel from a 1933 newspaper comic strip" and "panel" outranks the negative. The
style block is shared and never varied, so the border comes off in post instead.

## Publishing a LoRA

```bash
scripts/publish-lora.sh wilson-v1.safetensors \
  --character wilson --id wilson-character-v1 --kind character \
  --base-model sdxl-1.0 --trigger wlsnfnce --strength 0.8
```

It validates the registry before uploading and again after writing the card, and it is the
only supported way to write a card's `sha256` and `bytes` — everywhere else in this registry
those are recomputed at build time, but the weights are not in the tree to hash.

A **style** LoRA defaults to training on `training-set` + `style-plate`. Leave the
character-free plates out and the style LoRA memorises the leads, and every character then
drifts toward them. `--dry-run` prints the card and touches nothing.

## Caching and CORS

`nginx.conf` sets both, and the numbers follow one rule: **stale canon is the failure mode
that has actually hurt here.** Images get `max-age=86400, s-maxage=300`; every JSON endpoint
gets `max-age=300, s-maxage=60`. The edge cap is tight because purging Cloudflare is not
available on the current API token — a plain `max-age=86400` once left the old cast pinned
at the edge for a day. JSON is tighter still than images: a stale sheet is cosmetic, a stale
`cast.json` points a consumer at an asset that no longer exists.

CORS (`Access-Control-Allow-Origin: *`) is on the JSON *and* on the bytes. Without it a
consumer that draws a sheet into a `<canvas>` taints it, and every downstream read of that
canvas then fails.

## Style

One rule above all: the style block in `style/vaudeville-1933.md` is **shared and never
varied per render**. Vary staging and camera, not style. Ake is the only colour accent in an
otherwise sepia world; keep it that way.

The `.md` is the source. `/style/vaudeville-1933.json` is projected from it at build time by
parsing the fenced blocks, so the two cannot drift — a hand-maintained copy would go stale
the first time the style changed. It did, once. That is why the character-tokens section of
that file is now a pointer instead of a duplicate.
